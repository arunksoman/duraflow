## Backend

The backend reads its settings in this order, each layer overriding the one before:

1. Built-in defaults (`backend/internal/config/config.go`).
2. An optional `config/config.yaml` next to the binary (or in `../config`).
3. `DURAFLOW_*` environment variables.

A YAML key becomes an environment variable by upper-casing it, replacing dots with underscores and
adding the `DURAFLOW_` prefix: `temporal.address` becomes `DURAFLOW_TEMPORAL_ADDRESS`.

| Key                              | Default                                  | What it does                                                                                     |
| -------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `roles` (`DURAFLOW_ROLES`)       | `api,worker`                             | What this process runs: `api`, `worker`, or both. See [Scaling](/docs/architecture/backend#scaling). |
| `server.host`                    | `0.0.0.0`                                | Interface to listen on.                                                                          |
| `server.port`                    | `8000`                                   | Port to listen on.                                                                               |
| `server.basePath`                | `/api`                                   | Prefix for every API route.                                                                      |
| `server.allowedOrigins`          | `http://localhost:5173`                  | CORS origins.                                                                                    |
| `database.driver`                | `sqlite`                                 | `sqlite` or `postgres`.                                                                          |
| `database.dsn`                   | `./data/duraflow.db?…` (WAL mode)        | Database connection string.                                                                      |
| `auth.jwtSecret`                 | `dev-only-change-me`                     | Secret used to sign session tokens. **Change it.**                                               |
| `auth.tokenTTL`                  | `24h`                                    | How long a login lasts.                                                                          |
| `seedAdmin.email`                | `admin@duraflow.local`                   | Admin created on first boot, when the users table is empty.                                      |
| `seedAdmin.password`             | `changeme123`                            | That admin's password. **Change it.**                                                            |
| `seedAdmin.name`                 | `Admin`                                  | That admin's display name.                                                                       |
| `temporal.address`               | `localhost:7233`                         | Temporal frontend gRPC address.                                                                  |
| `temporal.namespace`             | `default`                                | Temporal namespace every workflow runs in.                                                       |
| `telemetry.sinkURL`              | derived from the server address          | Where workflows send run events. **Required** on a worker-only process: an API copy's `/api/internal/zigflow/events`. |
| `telemetry.token`                | derived from `auth.jwtSecret`            | Shared secret workflows send with each event. The same on every copy that shares the JWT secret. |
| `telemetry.timeout`              | `1s`                                     | How long a workflow waits for the API to accept an event.                                        |
| `telemetry.maxEventBytes`        | `65536`                                  | Larger event payloads are stored truncated (the UI says so).                                     |
| `telemetry.retentionPerExecution`| `2000`                                   | Maximum number of events kept per run.                                                           |
| `worker.identity`                | `<hostname>:<pid>`                       | This worker process's name on the Workers page and in Temporal.                                  |
| `worker.refreshInterval`         | `5s`                                     | How often the pool re-reads which task queues to poll (a save also triggers it).                 |
| `worker.heartbeatInterval`       | `10s`                                    | How often a worker process reports itself on the Workers page; three missed means offline.       |
| `worker.deadlockDetectionTimeout`| `10s`                                    | Longest a workflow task may run: a version compile plus one run event delivery.                  |
| `worker.stopTimeout`             | `10s`                                    | How long in-flight activities get to finish on shutdown.                                         |
| `worker.maxConcurrentActivities` | `0` (Temporal's default)                 | Activities each process runs at once, per task queue.                                            |
| `worker.maxConcurrentWorkflowTasks` | `0` (Temporal's default)              | Workflow tasks each process runs at once, per task queue.                                        |
| `worker.cacheSize`               | `512`                                    | Compiled DSL versions each process keeps in memory.                                              |
| `worker.envPrefix`               | `ZIGGY`                                  | Environment variables with this prefix are available to workflows as `$env`. Keep them the same on every copy. |
| `worker.containerRuntime`        | `docker`                                 | Runtime for `run: container` steps: `docker` or `kubernetes`.                                    |
| `worker.containerNamespace`      | (empty)                                  | Kubernetes namespace for `run: container` steps.                                                 |
| `worker.containerServiceAccount` | (empty)                                  | Kubernetes service account for `run: container` steps.                                           |
| `worker.logLevel`                | `warn`                                   | Zigflow's own log level.                                                                         |

### Postgres

SQLite is the default. To use Postgres, set:

```sh
DURAFLOW_DATABASE_DRIVER=postgres
DURAFLOW_DATABASE_DSN="host=db user=duraflow password=… dbname=duraflow sslmode=disable"
```

The schema is created and migrated automatically on every start. There are no migration files to
run. Postgres is required to run the `api` and `worker` roles as separate processes, or to run more
than one copy of either.

## Frontend

| Variable       | Default                      | What it does                                                                                  |
| -------------- | ---------------------------- | --------------------------------------------------------------------------------------------- |
| `API_BASE_URL` | `http://localhost:8000/api`  | Where the frontend's server reaches the backend API. The browser never calls the API directly. |
| `ORIGIN`       | (inferred)                   | The public URL of the frontend. Set it when serving the production build behind anything but `http://localhost`. |
| `PORT`, `HOST` | `3000`, `0.0.0.0`            | Where the production Node server listens (`adapter-node`).                                     |

## Docker Compose

`docker-compose.yml` wires the three services together: it points the backend at the `temporal`
service, points the frontend at the `backend` service, mounts `backend/data` for persistence and
sets the development admin and JWT secret. Edit the `environment:` blocks to change any of the
settings above, without rebuilding the images.

`docker-compose.scale.yml`, layered on top, runs the scaled-out shape: Postgres, two `api` copies
behind nginx and two `worker` copies.

```sh
docker compose -f docker-compose.yml -f docker-compose.scale.yml up --build
```
