Duraflow is an open-source visual builder and run console for durable workflows. You draw a
workflow as a flowchart: call an API, set some variables, branch, loop, run steps in parallel,
wait, retry. Duraflow turns it into a [Zigflow](https://github.com/zigflow/zigflow) workflow
definition that runs on [Temporal](https://temporal.io/). When it runs, the canvas lights up with
the path the run actually took: which steps succeeded, which failed, which branches were skipped,
and the exact input and output of every step.

## Why Duraflow

Temporal guarantees that a workflow finishes, even across crashes, deploys and flaky third-party
APIs. Getting there usually means writing and deploying worker code for every workflow, and
reconstructing what happened from event histories when a run misbehaves.

Zigflow removes the first problem: workflows are declared in YAML, based on the
[CNCF Serverless Workflow](https://serverlessworkflow.io/) specification, and run on Temporal
without any worker code. Duraflow adds the rest:

- **A visual editor that keeps the DSL honest.** The canvas is always derived from the YAML, and
  the YAML is always one click away and editable in both directions. What you see is exactly what
  runs.
- **A run console that speaks your design.** Runs are shown on the same canvas you designed, not as
  Temporal event histories.
- **A platform around it.** Projects, a cross-project run list, schedules, and one supervised
  Zigflow worker per workflow, started for you when you save.

## Project status

Duraflow is young and moving quickly. The builder, real execution, schedules and run
observability work end to end. Backfills are modelled in the API and UI but are not produced yet,
and a few advanced task options can only be edited in the DSL view. Expect rough edges and
breaking changes.
